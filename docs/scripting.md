# Scripting: ScriptServer and native script classes

Status: first pass 2026-10-03 (pass5 decompilation, no runtime capture yet).
Confidence levels follow `docs/confirmed.md`. This document supersedes the stub in
`docs/engine-reconstruction.md` §10 and resolves hypothesis H-B4 (`docs/hypotheses.md`).

## 1. Overview

Level scripting is data-driven. Disc records of the ScriptServer (server id 4; record prefixes `SCR_`,
`SCP_`, `ESC_`, see `docs/formats.md`) name a **script class** such as `SCR_Fog`, `SCR_PlayFX` or
`SCR_MountPegasus`. The executable registers a native implementation for each class name at start-up.
When a record is loaded, the ScriptServer looks the name up and copies the native callbacks into the
new object. There is no bytecode interpreter in the code read so far: the "script" is the record's
parameter block plus the native functions. HIGH.

## 2. Native registration. HIGH

| Function | Reading |
|---|---|
| `FUN_0013ec60` | creates the descriptor pool `DAT_002d7984` on first use: `FUN_0014ad10(heap, 0x1c, 0x20, 0x20, 4)` (0x1c-byte entries, 32 per block) |
| `FUN_0013ec20` | allocates one descriptor from that pool |
| `FUN_00140088(name, desc)` | inserts the descriptor into the current name dictionary: `Dict_Insert(Dict_GetCurrent(), name, desc)` |
| `FUN_001400c8(name, fn)` | short form: new descriptor with only slot 3 set to `fn`, then `FUN_00140088` |

**Native descriptor** (0x1c bytes, 7 slots):

| Slot | Offset | Use | Level |
|---|---|---|---|
| 0 | `+0x00` | called once when a script object is created from a record (`FUN_0013f3e0`) | HIGH |
| 1 | `+0x04` | **attach**: creates the class's runtime object at instance `+0x50` from the parameter block (`+0x54` base + `+0x5c` offset), installs the release callback `+0x48` and, when the instance flag `+4 & 4` is set and the parent is not suspended, the per-frame tick `+0x3c`, then activates (example `SCR_CameraShake` `FUN_00285df8`, `SCR_Mirror` `FUN_00281788`) | HIGH |
| 3 | `+0x0c` | **trigger**: the main native; the only slot set by `FUN_001400c8`. For full descriptors it re-activates the runtime object (`FUN_00285eb0` → `FUN_00196a08`) | HIGH |
| 6 | `+0x18` | **destroy**: deletes the runtime object at `+0x50` and clears it (`FUN_00285ed0`, `FUN_00281860`) | HIGH |
| 2, 4, 5 | | always 0 in the registrations found | HIGH |

Registrations are made by 39 functions, most of them `init` functions for one gameplay feature
(`FUN_001b4c48` Pegasus, `FUN_001a9a58` Medusa head, `FUN_0019c3f8` Earth magic, `FUN_001c0500` wind,
`FUN_00251948` player/character utilities, `FUN_0025a1f0` engine environment classes).
renMaster registers its effect classes with built names (`"SCR_%s"`); see `docs/rendering.md`.

The full list (143 literal registrations) is generated by `tools/scr_registry.py` into
`analysis/scr_registry.tsv` (name, registering function, slots 1/3/6).

## 3. Script objects (0x50 bytes). MEDIUM

Created by the ScriptServer default bank (`FUN_0013f520` → `FUN_0013f3e0(obj, record header, record)`)
or at run time by natives (`FUN_0013f230(obj, header, fn)`, 24 callers; then ScriptServer virtual
`+0x2c` adds it).

| Offset | Meaning | Source |
|---|---|---|
| `+0x00` | server id 4 | |
| `+0x08` | name, 24 bytes | record header `+0x08` |
| `+0x20`, `+0x22` | u16 | record `+0x1e`, `+0x1c` |
| `+0x24` … `+0x3c` | copy of the 7 native slots | descriptor found with `Obj_FindByName(record + 4)` (`FUN_0013f1b8`); default `DAT_002d7990` |
| `+0x40`, `+0x42` | u16 flags | record `+0x22`, `+0x20` |
| `+0x44` | parameter block (heap copy, 16-byte aligned) | record `+0x24` onwards |
| `+0x48` | parameter block size | record size − 0x24 |
| `+0x4c` | parameter count area: `record[+0x24] · 4 + 4` when flag `+0x20 & 8` | |

`FUN_0013f230` builds the same layout with the default name at `DAT_002e8f10` and the given function in
slot 3.

## 4. ScriptServer. MEDIUM

- Constructor `FUN_0013fe48`: pooled server (id 4) with vtable `0x2f5298`, update key `0x6000`.
- `FUN_0013f8e8` (vtable slot, per frame): pushes a frame-scratch allocator
  (`DAT_003632e0` stack, `FUN_0014d2e8`), walks the active script list at `+0x24`, switches the current
  WAD/context (server `0x16` virtual `+0x84`/`+0x8c`) to the script's owner, calls the script's update
  through its vtable `+0x18`, and restores the context.
- `FUN_0013ef28` (vtable slot): depth-first walk over a node tree (child list `+0x24`, stack of 16).
  For each node with wait counter `+0x2a == 0` and `+0x4c != 0`: sets the current-script global
  `DAT_002d7988`, pushes the node's context (`FUN_00142e08`) when it has a list at `+0xb4`, calls
  `+0x3c`, and stores the returned wait (`+0x28`) in `+0x2a`; otherwise counts `+0x2a` down. LOW: the
  relation between these nodes and the 0x50 script objects is not settled.
- `FUN_0013ebe8(handle)`: ScriptServer virtual `+0xa4` looks a script up; returns its `+0x88`.

## 5. Native calling convention. MEDIUM

Script instance fields seen from the natives (all natives take the instance as their only argument):

| Offset | Meaning | Level |
|---|---|---|
| `+0x04` | u16 flags; bit 2 = start ticking on attach | MEDIUM |
| `+0x18` | parent instance (its flag bit 0 suspends children) | MEDIUM |
| `+0x28` / `+0x2a` | requested / current wait in frames; `0xffff` (−1) = wait until released | MEDIUM |
| `+0x3c` | per-frame tick function | HIGH |
| `+0x48` | release callback | HIGH |
| `+0x50` | runtime object owned by the class | HIGH |
| `+0x54`, `+0x5c` | parameter block base and offset | MEDIUM |
| `+0x64` | target object handle (handle table `0x2d8924`); for scripts started by moves, the owner character's node | ~~MEDIUM~~ HIGH (2026-10-03, `docs/magic.md` §1) |
| `+0x68` | the move instance that started the script (move-started scripts) | HIGH |
| `+0x6c` | the action record that started it; natives read fixed parameters from it | HIGH |
| `+0x70` | the class name hash | HIGH |
| `+0x74` | the per-class parameter block (action `+0x0c`) | HIGH |


Slot-3 natives take one argument, a script context object. Example `SCR_NoShadow` (`FUN_00251128`):
reads the target handle at `+0x64` through the handle table `0x2d8924`, toggles the target's
shadow, stores a completion callback at `+0x48` and sets `+0x2a = 0xffff` (wait until released).

## 6. Missed functions

16 native callbacks were not function starts in Ghidra pass5 (for example `SCR_ClearVelocity`
`0x002518e8`, `SCR_NoPlayerJumping` `0x00251678`, `SCR_EnterFlight` `0x00193b20`). A scan for
addresses built with `lui` + `addiu` right after a `jr ra` (`tools/missed_functions.py`) finds 52 such
starts in game code; `ApplyCore.java` now creates them (pass6).

Pass6 (2026-10-03) created all 52 (6,459 functions). Some natives were still missing: GCC pads the gap
after `jr ra` + delay slot with one `nop` for 8-byte alignment, so the start is three words after the
return, not two (`SCR_ClearVelocity` `0x002518e8`, `SCR_NoPlayerJumping` `0x00251678`,
`SCR_FleeceIsActive` `0x00251830`). The scan now accepts that case and finds 35 more starts on pass6;
pass7 creates them.

Pass7 (2026-10-03): 6,497 functions; all 124 starts the fixed scan finds against pass5 now exist
(`analysis/missed_functions.tsv` keeps the union so later passes recreate them). The 155 native names
from `symbols.tsv` are applied (`Scr_ClearVelocity` etc.). The scan finds no further starts on pass7.

## 7. Worked example: `SCR_Teleport` (`FUN_001935a8`). HIGH

1. Resolve the target object from the handle at instance `+0x64`.
2. Parameters at `*(instance + 0x6c)`: `+0x14` s16 site number, `+0x18` f32 heading in degrees.
3. Format `"Site%d"` and find that node in the current level (`FUN_001fee88`, `FUN_0018f588`); take its
   world position (`FUN_0018f450`).
4. Build a rotation from the heading (`degrees / 360 · 2π`, `FUN_0018baf0`) with the site position as
   translation, and pass the matrix to the target's virtual `+0x2c` (set world matrix).
5. Set the wait to `0xffff`.

## 8. Worked example: `SCR_PlayFX` (`FUN_001b5798`). MEDIUM

Slot-3 native that spawns a particle/effect resource on the target object. 3,780 bytes; most of the
size is inlined VU0 matrix products. Read from pass6.

**Parameter block** at `*(instance + 0x74)` (word indices):

| Offset | Meaning | Level |
|---|---|---|
| `+0x00` | effect name hash (compared with `Hash_Name` of node names when stopping) | HIGH |
| `+0x04` | attach joint name hash; 0 = object root. Resolved with `FUN_001456b0(skeleton at obj+0x104, hash)` | HIGH |
| `+0x08` | passed to `FUN_00267020(value, spawned effect)` after spawn; meaning open | LOW |
| `+0x24`, `+0x28`, `+0x2c` | offset rotation in degrees (X, Y, Z); `FUN_001b5358` converts (`deg / 360 · 2π`, `FUN_0018be40`) and builds the local offset matrix | HIGH |
| `+0x30` | u16 flags (below) | MEDIUM |

**Flags** (`+0x30`):

| Bit | Reading | Level |
|---|---|---|
| `0x1` | passed to the spawn call `FUN_002666f8` | LOW |
| `0x2` | lifetime tied to the target: spawn a helper script (`FUN_0013f230` with tick `FUN_001b5180`) that kills the effect when the target handle dies; otherwise the release callback `+0x48` is `FUN_001b5278` (marks the effect done, flag `|= 2`, on release) | MEDIUM |
| `0x4` | **stop** instead of start: walk the target's script children (list at owner `+0xb4`), and for each node whose name hash equals `+0x00`, set flags `|= 3` on its `FUN_001b5180` helper | MEDIUM |
| `0x8` | sync to the target's animation: reset the effect's animation nodes (`FUN_00100728(-1.0, …)`, rate 0) and add a helper script with tick `FUN_001b4f28` that scales each effect clip's rate by the target clip's rate (`FUN_00100bc0 / FUN_00100b60`) | MEDIUM |
| `0x10` | parent the effect to the object (or the joint) with `FUN_0013d1b0(obj, fx, joint or 0xfffd)` so it follows; otherwise the world matrix is computed once (joint or object world matrix × offset) and written to the effect node | MEDIUM |
| `0x20`, `0x40` | attach to one of two sub-objects returned by the target's virtual `+0x74` (`0x20` picks entry 0, `0x40` entry 1); possibly the two hands or weapons | LOW |
| `0x80` | with a joint: extra orientation step at the end (VU0 code not recovered) | LOW |
| `0x100` | use the object referenced by target `+0x1c0` (rider/owner) when it exists | MEDIUM |

**Steps:**

1. Resolve the target from the handle at `+0x64` (`g_HandleTable`). If the instance has a parameter
   pointer `+0x6c`, register it with the target's script list at `obj+0x1c8` (`FUN_0024d348`); if an
   instance of the same kind (6) is already running (`FUN_0024d430`), share its release callback and
   effect handle and stop.
2. Find the effect resource: `FUN_001b5600` searches the target's own WAD, then the two loaded level
   WADs at `DAT_0036a8a0[0..1]` (when their flag `8` is set), then the common WAD `DAT_0036a8b4` (flag
   `4`), and finally the target WAD again. `FUN_001b5540` does the name lookup in one WAD.
3. Switch the WAD context, get the effect manager (`FUN_00265f10`) and spawn (`FUN_002666f8`). The
   returned record has `[0]` state (negative = failed), `[1]` effect handle (stored at instance
   `+0x7c`) and `[4]` the scene node.
4. Place the node (flags `0x10`/`0x20`/`0x40`, joint, offset matrix). Node matrices follow the scene
   node layout: `+0x20` local 4×4, `+0x60` parent index (−1 = root), `+0x68` stamp, `+0x70` cached
   world; writing a matrix increments `g_MatrixStamp`.
5. If the target has flag `0x200000` at `+0x174`, call `FUN_0013d7e0(node, 2)`.
6. Without a release callback, unregister from the target (`FUN_0024d3b0`). Set the wait to `0xffff`.

Helpers: `FUN_001b5070` (helper tick: re-parents and finishes the effect when the target is gone),
`FUN_001b4ee0` (helper tick for flag `0x8`: detaches from its parent and finishes).
